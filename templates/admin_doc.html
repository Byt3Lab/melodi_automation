1. Concepts Fondamentaux

Le MELODI Automation Engine est un moteur d'orchestration visuel (inspiré de n8n) permettant d'automatiser des flux métiers complexes à travers l'ERP sans écrire de code de plomberie.

Graphes Dirigés (DAG)
Un workflow est un graphe de nœuds du registre actuel (core.* ou nœuds de modules), reliés par des connexions et des ports de sortie.
Ports Multi-Sorties
Chaque nœud dispose de ports d'entrée et de sortie spécifiques (ex: true / false, case_1 / default, item / done).
Contexte & Isolation
Chaque nœud a un identifiant consultable dans l'inspecteur. Le contexte fournit le payload initial, l'entrée courante et les résultats indexés par ID.
Seuls les nœuds du registre actuel sont exécutés (core.trigger_event, core.if_else, core.module_action, etc.). Les anciens types génériques trigger, condition et action ne sont plus convertis automatiquement; les workflows qui les contiennent doivent être reconstruits avec les nœuds actuels.
Historique : chaque modification de la définition crée une révision immuable. Depuis le constructeur, ouvrez l'historique pour consulter ou restaurer une version; une restauration crée toujours un nouveau numéro. Les workflows existants démarrent avec un snapshot de leur état courant; leurs définitions antérieures ne peuvent pas être reconstituées.

2. Déclencheurs (Triggers & Webhooks)

Un workflow démarre toujours par un nœud Déclencheur. Deux types de déclencheurs sont supportés :

A. Déclencheur Événementiel (Event Trigger)

Le workflow s'abonne au module et à l'événement configurés dans le nœud core.trigger_event. Les données émises par l'événement sont disponibles comme objet JSON dans payload. Comme le déclencheur webhook, ce nœud transmet uniquement cet objet métier aux étapes suivantes; les informations du déclenchement restent dans le contexte complet.

// Même forme de contexte pour tous les déclencheurs :
{
  "event": { "module": "commerce", "name": "order.created" },
  "payload": {
    "order": { "id": 402, "customer": "Société Alpha", "total": 185000 }
  }
}
B. Déclencheur Webhook Entrant (Webhook Trigger)

Le body JSON doit contenir un objet payload. Le test de workflow demande uniquement les données métier et construit cette enveloppe automatiquement. Le nœud transmet ensuite directement le contenu de payload aux étapes suivantes; les détails HTTP restent dans le contexte d'exécution sous webhook. Le type de déclencheur peut être changé dans les paramètres du constructeur.

  • URL dédiée : /api/melodi_automation/webhook/<votre_token>
  • Méthodes acceptées : POST, GET, PUT, DELETE.
  • Sécurité : Le token est unique et peut être régénéré à tout moment depuis les paramètres du workflow en cas de compromission.
curl -X POST https://votre-domaine.com/api/melodi_automation/webhook/wh_xxxxxxxx \
  -H "Content-Type: application/json" \
  -d '{"payload": {"customer": "Alpha", "amount": 15000, "status": "paid"}}'

Dans les nœuds suivants, utilisez {payload.customer} ou {payload.amount}. Les métadonnées HTTP restent disponibles dans le contexte webhook.

3. Nœuds de Contrôle de Flux (Flow)

Nœud Fonctionnement Ports de sortie & Routage
Si / Sinon (If / Else)
Évalue une ou plusieurs règles logiques (ET / OU) sur n'importe quel champ (ex: payload.total > 50000). true : Si la condition est vraie.
false : Si la condition est fausse.
Aiguillage (Switch)
Examine la valeur d'une variable (ex: payload.status) et oriente le flux vers le cas correspondant (ex: paid, pending, cancelled). Chaque cas configuré active son port sortant dédié (ex: case_1, case_2). Si aucun cas ne correspond, le port default est activé.
Boucle (Iterator)
Parcourt un tableau d'éléments (ex: payload.items ou input.records). Le nœud produit items et count, puis active actuellement les ports item et done lors de la même exécution. Il ne répète pas encore les nœuds en aval pour chaque élément.
Appeler un Sub-Workflow
Exécute un sous-workflow de façon synchrone ou asynchrone avec transmission de données et protection stricte contre les boucles récursives et le dépassement de profondeur. main : Si le sous-workflow se termine avec succès.
error : Si le workflow est introuvable, inactif, échoue ou si une boucle récursive est détectée.
Requête HTTP
Effectue un appel API externe asynchrone (GET, POST, PUT, DELETE) vers un service tiers ou webhook sortant avec headers et payload JSON. main : Contient la réponse HTTP (status_code, body, headers).
Entrées et sorties : un port d'entrée (souvent main) est l'endroit où arrive un fil. Un port de sortie indique quelle connexion est suivie. Le moteur compare l'identifiant de sortie de la connexion à active_ports renvoyé par le nœud. Les ports d'entrée sont enregistrés pour le graphe, mais ne sélectionnent pas ni ne transforment les données reçues : dans une chaîne simple, le nœud reçoit la sortie précédente sous input. Une condition If/Else active true ou false; un Switch active l'ID du cas correspondant ou default; un nœud ordinaire active main.

4. Définition de Variables (Set Fields)

Le nœud Définir des Variables (core.set_fields) crée un objet de sortie à partir des données d'entrée. Les valeurs peuvent être fixes ou interpolées depuis le contexte.

Deux Modes d'Assignation :
  • Fusionner (merge) : Conserve toutes les données déjà présentes en entrée et ajoute (ou écrase) uniquement les variables spécifiées. Idéal pour enrichir un payload sans perdre les informations d'origine.
  • Remplacer complètement (replace) : Efface les données d'entrée et ne conserve strictement que les variables déclarées dans la liste. Idéal pour préparer un payload épuré avant un appel API ou l'envoi d'un webhook.
Exemple Set Fields

Avec le payload initial ci-dessous, configurez le mode merge et ces champs. Le taux est converti en nombre et l'expression entre accolades conserve le type JSON de la valeur résolue.

{
  "payload": {
    "order": { "id": "CMD-204", "subtotal": 12000 }
  }
}

[
  { "key": "order_id", "value": "{payload.order.id}", "type": "string" },
  { "key": "subtotal", "value": "{payload.order.subtotal}", "type": "number" },
  { "key": "tax_rate", "value": "0.1925", "type": "number" },
  { "key": "tag", "value": "WEB", "type": "string" }
]

En mode merge, la sortie conserve l'objet d'entrée et ajoute ces champs au niveau racine. En mode replace, elle ne contient que les champs configurés.

Transformation avec Code Transform

Reliez ensuite un nœud core.code_transform et utilisez l'expression Python restreinte ci-dessous. input désigne la sortie Set Fields précédente; payload reste la donnée d'origine.

{'order_id': input.get('order_id'),
 'total_ttc': round(input.get('subtotal', 0) * (1 + input.get('tax_rate', 0)), 2),
 'tag': input.get('tag')}

# Résultat : {"order_id": "CMD-204", "total_ttc": 14310.0, "tag": "WEB"}

L'expression est évaluée avec un ensemble restreint de fonctions (round, sum, len, conversions usuelles et json); l'import de modules et les accès système ne sont pas disponibles.

Interpolation Dynamique de Variables :

Vous pouvez utiliser la syntaxe entre accolades {...} pour injecter dynamiquement des valeurs provenant des étapes précédentes :

PatternDescriptionExemple
{payload.chemin}Accède à la donnée initiale commune aux déclencheurs event et webhook{payload.order.id}
{input.champ}Accède à la sortie courante précédente dans une chaîne linéaire; dans un graphe ramifié, préférez l'ID explicite sous steps{input.total_ttc}
{steps.ID_DU_NOEUD.champ}Accède au résultat d'un nœud précis, même après d'autres étapes{steps.node_prepare.order_id}
{context}Dans Code Transform, objet du contexte d'exécution completcontext['steps']['node_prepare']['order_id']
Retrouver l'ID : sélectionnez un nœud sur le canvas. Son identifiant est affiché dans l'en-tête de l'inspecteur, à côté de son type (par exemple ID: node_prepare). Les sorties exécutées sont rangées sous steps avec cette clé exacte. Les ID générés par le constructeur utilisent des caractères alphanumériques et des tirets bas.

5. Comment Fonctionne le Bouton « Tester ce Nœud »

Dans le tiroir de configuration d'un nœud, un bouton « Lancer le test du nœud » permet de valider le comportement d'une étape en isolation.

Que fait exactement ce bouton ?
  1. Le navigateur envoie une requête POST /api/melodi_automation/nodes/test-step contenant le type de nœud, sa configuration actuelle et le payload simulé défini dans le champ texte.
  2. Le serveur exécute uniquement la méthode execute(...) de ce nœud dans un environnement cloisonné.
  3. Le moteur ne déclenche aucun des nœuds situés en aval et ne persiste aucune trace d'exécution globale dans la table des exécutions.
  4. Le résultat renvoie l'objet généré (output_data) ainsi que les ports de sortie activés (active_ports), ce qui permet de voir immédiatement quelle branche conditionnelle sera empruntée.
Vous pouvez personnaliser librement le JSON simulé dans le tiroir d'inspection pour tester différents scénarios métiers (ex: statut "paid", montant supérieur à un seuil, etc.).

6. Exposer des Nœuds depuis vos Modules Tiers

Conformément aux directives d'architecture de MELODI (AGENTS.md), les modules métier collaborent sans couplage direct à travers le système de Hooks.

Pour exposer vos propres nœuds métier dans la bibliothèque de l'Automation Engine, votre module exécute l'action register_node (ou register_nodes) fournie par le module melodi_automation lors de son initialisation (dans load()).

Exemple d'enregistrement dans modules/melodi_wallet/module.py :
class MelodiWalletModule(ApplicationModule):

    def _register_actions(self):
        # 1. Vos actions métier habituelles
        self.add_action("pay_invoice", self.action_pay_invoice)

    async def load(self):
        # ... permissions, routes, etc.

        # 2. Enregistrement de nœuds personnalisés auprès de melodi_automation via son action hook
        await self.app.hook_manager.action.execute(
            "melodi_automation",
            "register_node",
            {
                "id": "melodi_wallet.pay_invoice",
                "name": "Portefeuille: Payer Facture",
                "category": "business",  # triggers, logic, actions, data, integration, business
                "description": "Débite automatiquement un portefeuille pour régler une facture",
                "module": "melodi_wallet",
                "action": "pay_invoice",
                "icon": "account_balance_wallet",
                "color": "#10b981",
                "schema": {
                    "wallet_id": {
                        "type": "string",
                        "label": "Identifiant du Portefeuille",
                        "required": True,
                        "description": "Supporte l'interpolation : {payload.wallet_id}"
                    },
                    "amount": {
                        "type": "number",
                        "label": "Montant du débit",
                        "required": True
                    }
                },
                "outputs": [
                    {"id": "main", "label": "Paiement réussi", "color": "#10b981"}
                ]
            }
        )
Propagation du résultat : Lorsque ce nœud personnalisé est exécuté dans un workflow, l'Automation Engine appelle await app.hook_manager.action.execute("melodi_wallet", "pay_invoice", resolved_parameters). Le dictionnaire renvoyé par votre méthode est automatiquement disponible pour les nœuds suivants sous input et sous steps.<node_id>.
Nœud Requête HTTP Avancé & Pièces Jointes :

Le nœud Requête HTTP / Webhook Sortant (core.http_request) prend en charge les requêtes complexes avec authentification (Bearer, Basic Auth, API Key Header) et l'envoi de formulaires multipart avec pièces jointes : 

# Exemple de configuration d'envoi multipart avec pièces jointes dans un nœud HTTP :
{
  "method": "POST",
  "url": "https://api.tiers.com/v1/documents",
  "auth_type": "bearer",
  "auth_token": "{payload.api_key}",
  "body_type": "form_data",
  "form_fields": {
    "title": "Facture {payload.invoice_number}",
    "client_id": "{payload.customer_id}"
  },
  "files": [
    {
      "field_name": "document",
      "file_source": "path",       # "path" | "media_id" | "base64" | "content"
      "file_path": "/var/storage/invoices/inv_{payload.id}.pdf",
      "filename": "facture_{payload.id}.pdf"
    },
    {
      "field_name": "receipt",
      "file_source": "media_id",   # Résout automatiquement depuis la table des médias MELODI
      "media_id": "{payload.receipt_media_id}"
    }
  ]
}

7. Importation & Exportation de Workflows

Les workflows peuvent être facilement exportés et réimportés d'un environnement MELODI à un autre (développement, staging, production) sous forme de fichiers JSON portables.

Exportation (via API & Fetch)

Cliquez sur l'icône de téléchargement dans la liste des workflows ou depuis le constructeur. Une requête asynchrone GET /api/melodi_automation/workflows/export?id=<id> est envoyée via fetch(), déclenchant automatiquement le téléchargement et vous fournissant l'URL directe permanente /api/melodi_automation/workflows/download?id=<id>.

Importation

Cliquez sur le bouton « Importer » dans la barre supérieure des workflows. Vous pouvez téléverser le fichier JSON ou coller son contenu. Le workflow est instantanément créé en mode Brouillon (Inactif) pour vous permettre de le vérifier avant activation.

8. Module Démo (`melodi_automation_demo`) & Nœuds d'Exemple

Le module melodi_automation_demo sert d'illustration concrète de l'extension de l'Automation Engine par des modules tiers sans couplage SQL direct.

Nœud : Dump de Contexte (demo.context_dump)

Ce nœud enregistre l'intégralité du contexte d'exécution du workflow (inputs, variables, étapes passées) dans un fichier JSON sous storage/automation_demo/dumps/.

Consultez les dumps enregistrés sur la page dédiée : Visualiseur de Dumps.

Nœud : Calculer Somme (demo.sum)

Ce nœud reçoit deux réels a et b (valeurs fixes ou expressions Jinja {...}) et renvoie leur somme dans la variable r. 

# Output produit par demo.sum :
{
  "a": 15.5,
  "b": 24.5,
  "r": 40.0
}
